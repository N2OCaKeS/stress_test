# cli

## Назначение

`cli` — кроссплатформенная консольная утилита для удобной работы со всеми сервисами платформы из терминала.

CLI нужен для:

- ручной работы администраторов и операторов;
- автоматизаций и скриптов;
- быстрого доступа к API без необходимости открывать web-интерфейс;
- стандартизированного взаимодействия со всеми сервисами через единый набор команд.

## Основные возможности

- выполнение команд ко всем backend-сервисам;
- авторизация пользователя и использование токенов доступа;
- автокомплит команд и параметров;
- единый формат вывода для всех поддерживаемых сервисов;
- использование в скриптах и автоматизациях.

## Поддерживаемые платформы

- `Windows 10`
- `Windows 11`
- `Astra Linux 1.7`
- `Astra Linux 1.8`
- `macOS`

## Границы ответственности

`cli` не хранит бизнес-данные платформы и не является отдельным доменом данных.

CLI отвечает за:

- удобный вызов внешних API сервисов;
- локальное хранение пользовательских настроек клиента;
- передачу токенов и параметров запросов;
- удобную оболочку над возможностями backend-сервисов.

CLI не отвечает за:

- хранение серверов, логов, токенов и ролей;
- проверку прав как источник истины;
- аудит как основное хранилище событий.

## Модель доступа

`cli` использует ту же модель доступа, что и backend-сервисы:

- роли пользователя определяются в `auth_service`;
- доступ к конкретному сервису определяется принадлежностью к отделу;
- конкретные операции разрешаются backend-сервисом по матрице прав;
- сам `cli` не создаёт и не изменяет роли.

CLI должен корректно обрабатывать:

- успешную авторизацию;
- отказ в доступе (`403 Forbidden`);
- отсутствие доступа к сервису для отдела;
- блокировку пользователя или бот-учётки.

## Интеграции

- `auth_service` — аутентификация и получение контекста прав;
- `config_service` — работа с секретами и токенами;
- `server_service` — управление серверами;
- `logging_service` — косвенный аудит всех действий через backend.

Все вызовы выполняются по внешнему API сервисов.

## Требования к UX

- понятный синтаксис команд;
- стабильный формат ошибок;
- автокомплит;
- кроссплатформенная работа;
- пригодность для использования в скриптах и CI.
