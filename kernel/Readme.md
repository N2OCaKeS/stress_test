# Kernel_benchmark

Комплекс нагрузочного тестирования ядра.

##

### Test 1 SEGMENTATION FAULT

Регрессионный тест на воспроизведение ошибки ядра Linux, при которой приложение может получить нулевые значения из корректно отображённых в память страниц файла.

Сбой проявляется при работе с `mmap`: вместо фактического содержимого страницы процесс читает нули. Если затронуты страницы с исполняемым кодом, это может приводить к аварийному завершению процесса.

Условия воспроизведения:

- приложение работает с файлом через `mmap`;
- отображаемый файл или исполняемый код расположен на `XFS`;
- в ядре включено обнуление освобождаемых страниц памяти: `init_on_free=1` или `CONFIG_INIT_ON_FREE_DEFAULT_ON=y`;
- в системе создаётся интенсивная нагрузка на память, из-за которой ядро активно выполняет `reclaim`;
- в синтетическом сценарии дополнительно отключается `transparent_hugepage` (`transparent_hugepage=never`), чтобы исключить влияние `THP` на результат теста.

Результат успешного воспроизведения:

- при создании нагрузки на подсистему памяти воспроизводится чтение нулей из `mmap`-страниц вместо реальных данных;
- в сценарии с исполнением кода из затронутых страниц процесс аварийно завершается с `segmentation fault`;
- завершение процесса-генератора нагрузки по `OOM Killer` возможно, но не является обязательным признаком ошибки.

### Test 2 XFS MEMORY LEAK

Регрессионный тест на воспроизведение ошибки ядра Linux, при которой при копировании или поиске файлов съедается USED память и не высвобождается.

Условия воспроизведения:

- создаем диск на 100 ГБ, форматируем установив тип файловой системы XFS и монтируем диск
- создаем 2 каталога на смонтированном диске (src и dest)
- в каталоге src создаем много случаных файлов
- копируем файлы из src в dest

Результат успешного воспроизведения:

- Память не высвобождается после копирования файлов, что подтверждает наличие утечки

### Test 3 USAGE OS RESOURCES

Нагрузочный тест на расход системных ресурсов ОС: сравнивает потребление CPU/RAM и служебную нагрузку на ядро (переключения контекста, прерывания, load average) в простое (`idle`) и под синтетической нагрузкой на CPU/RAM/диск/сеть (`load`).

Методика:

- `usage_os_resources.sh` собирает системные метрики раз в секунду в течение 600 секунд: без нагрузки (`idle`) и с нагрузкой (`load`);
- нагрузка создаётся стандартными утилитами ОС (`dd`, `nc`);
- в рейтинге используются только метрики ОС (`*_os.csv`) — вклад самих генераторов нагрузки вычтен, метрики хоста (`*_host.csv`) не учитываются.

Результат тестирования:

- Агрегированная оценка состояния системы под нагрузкой относительно простоя
