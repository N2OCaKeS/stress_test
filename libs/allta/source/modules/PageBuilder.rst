PageBuilder
=====================

.. note::
   Автор: команда ``allta``. Конструктор HTML-страниц для публикации в Confluence.
   ``add_chart`` автоматически строит макрос Table Filter and Charts ``table-chart``.

Назначение
----------

``PageBuilder`` собирает HTML-страницу из python-структур: заголовков, текста,
таблиц, галерей, графиков и вложений. Итоговый HTML можно сохранять локально
или публиковать через Confluence API.

Быстрый старт
-------------

.. code-block:: python

    from allta import PageBuilder

    builder = PageBuilder(title="Demo")
    builder.add_heading("Кратко")
    builder.add_paragraph("Описание отчёта")
    builder.add_header_table([
        {"label": "Params", "value": {"items": ["Users: 3000"]}},
        {"label": "ARM", "value": {"stand_number": "10"}},
    ])
    builder.add_table({
        "title": "Быстрые факты",
        "headers": ["Метрика", "Значение"],
        "rows": [["TPS", 42], ["Ошибки %", "0.1"]],
    })
    html = builder.render()

``add_header_table(rows, defaults=None)``
------------------------------------------------------------------------------------------------

Формирует «шапку» отчёта: таблицу ключ/значение с поддержкой списков и ссылок.
Автоматически добавляет строки ``Astra version`` и ``Kernel``.
Строка ``ARM`` заполняется по ``stand_number`` и всегда располагается перед ``Lead time``.
Прежнее имя ``add_details_table`` сохранено как алиас.

""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""
Принимаемые аргументы:
""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""

* ``rows``: Iterable — список строк (словарей или кортежей ``(label, value)``)
* ``defaults``: dict, optional — значения по умолчанию для отсутствующих ``value``

Форматы ``value``:

* ``str`` — выводится как текст (``\n`` → ``<br/>``)
* ``Sequence`` — выводится как список
* ``dict`` — можно комбинировать ``text``, ``link``/``href``/``url`` и ``items``

""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""

================================================================================================
ConfluencePublisher
================================================================================================

Класс ``ConfluencePublisher`` публикует HTML-страницы в Confluence и прикрепляет вложения.
Работает поверх клиента ``atlassian.Confluence`` и умеет строить версионное дерево страниц.

Особенности поведения
---------------------

1. Уникальность title в Confluence обеспечивается «невидимыми» суффиксами (zero-width символы).
2. При ``create_tree=True`` строится дерево версий: global → detailed → more.
3. Для трёхчастной числовой версии (``X.Y.Z``) имя родителя влияет на токен уникальности.
4. В ветке detailed имя страницы и вложений может быть переписано (full → detailed версия).

""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""

------------------------------------------------------------------------------------------------
``publish_results_from_params(...)``
------------------------------------------------------------------------------------------------

Высокоуровневая публикация отчёта с построением дерева версий и копии в detailed-ветке.

""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""
Принимаемые аргументы:
""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""

* ``conf_space``: str — space key
* ``conf_parent_page``: str|None — видимый родитель (контейнер)
* ``conf_new_page_name``: str — видимое имя страницы отчёта
* ``test_cycle_version``: str|None — версия (например ``1.8.4.46`` или ``1.7.5.UU.2``)
* ``body``: PageBuilder — объект с методом ``render()``
* ``attachments_dir``: Path|str|None — каталог с вложениями (все файлы будут прикреплены)
* ``attachments``: Sequence[str|Path]|None — дополнительные вложения
  Можно передать ``builder.attachments`` (список, собранный из add_attachment/add_gallery).
* ``create_tree``: bool — строить версионное дерево (default True)
* ``debug``: bool — режим публикации:
  ``False`` — под зашитым root parent библиотеки, ``True`` — под homepage ``conf_space``

Поведение:

* При ``create_tree=False`` или отсутствии версии публикуется только страница под parent (если задан).
* При ``create_tree=True`` создаются контейнеры global → detailed → more.
* Если задан ``conf_parent_page``, под версионными узлами создаются контейнеры
  ``STRESS_report <version> ⬝ <conf_parent_page>`` с макросом children.
* Под этими контейнерами публикуются 2 конечные страницы: основная (more) и релизная (detailed).
* Если в имени страницы/вложений есть full-версия (more), в detailed-ветке она заменяется на detailed.

Возвращает:
""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""""

* ``dict`` — ``{"page_id": <id_more>, "release_page_id": <id_detailed>|None}``
